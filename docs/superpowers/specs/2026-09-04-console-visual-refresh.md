# DomainHunter 侦测台视觉重构规格

**状态：** 待用户审核  
**日期：** 2026-09-04  
**范围：** 已完成的“候选收件箱 + 独立候选详情”前端的视觉与布局重构。

## 1. 目标

将现有偏暖白、低密度的审核界面改为“侦测台”视觉：等宽信息层级、高信息密度、明确状态标签、深浅主题切换，以及固定的审核决策区。

产品仍是候选审核工具，不是运维后台。页面继续只帮助用户判断：这个域名为何可能是新网站、是否可访问、是否像值得关注的产品，以及是否应由人工审核决定。

## 2. 不变的事实边界

- 仅使用已有真实接口：`/v1/review-queue`、`/v1/candidates/{id}/review-context`、审核决定接口与严格扫描接口。
- 不使用 mock 数据、浏览器估算值或虚构 CT、RDAP、DNS、HTTP、延迟、TLS 等事实。
- 严格核验快照缺失时，显示 `未验证`，绝不显示通过。
- 严格扫描的 `completed`、`no_candidates` 与失败保持三个不同状态。
- 不恢复 Ops、Analytics、全局 KPI 或后台参数页面。
- 继续保留独立详情 URL、外部链接安全属性、审核人 ID、冲突处理及返回收件箱后的搜索/滚动恢复。

## 3. 全局视觉系统

### 3.1 风格

- 基调：精确、安静的侦测台，而非霓虹终端或全屏监控大盘。
- 域名、分数、版本、时间、状态代码采用等宽字体；说明性正文采用系统无衬线字体。
- 卡片使用细边框、小圆角和低对比阴影；列表通过分隔线组织，不堆叠大量独立大卡片。
- 动画仅用于骨架屏、状态印记和轻量的列表进入；尊重 `prefers-reduced-motion`。

### 3.2 深浅主题

- 顶栏提供显式主题切换按钮。
- 选择存入 `localStorage`，刷新与后续访问保持。
- 浅色：雾白/石板灰底色、白色信息面板、蓝色主操作。
- 深色：深蓝灰底色、近黑面板、低亮度边框、蓝色主操作。
- 通过/失败/未验证在两种主题中均同时具备文字、图标或布局提示，颜色不单独承载语义。

### 3.3 状态徽章

| 服务端状态 | 用户可见文案 | 视觉含义 |
| --- | --- | --- |
| `passed` | 通过 | 绿色点或对勾 + PASS/通过标签 |
| `failed` | 不通过 | 红色图标 + FAIL/不通过标签 |
| `unknown` 或缺失 | 未验证 | 灰/琥珀图标 + 未验证标签 |

不得把 `unknown` 写成“待通过”“大概率可访问”或任何正向推断。

## 4. 候选收件箱

### 4.1 顶栏

仅包含：品牌 `DomainHunter`、当前页面名称“候选收件箱”、主题切换、扫描新网站按钮。不得加入后台导航、环境名、语言切换、全局审核人输入框或 KPI。

### 4.2 主候选

排序第一的待审核候选显示在“最高优先级”区：

- 大号等宽域名、产品名（存在时）、结论标签与真实优先级；
- 新网站与可访问性两项状态徽章；
- 一条真实产品证据；
- 明确的“查看证据 →”入口。

视觉应比列表项更突出，但其文案不得暗示已批准或可发布。

### 4.3 其他候选

其余候选使用一个连续的紧凑列表容器，每个项目通过分隔线区分：域名、可选产品名或摘要、两个状态、真实优先级和“查看证据”。

搜索仍是唯一首版过滤方式。加载、无结果、全部处理完与读取失败需要清晰保留，并且失败时不清空已显示候选。

## 5. 扫描弹层

扫描入口仍然是一次真实严格扫描。弹层分为四种状态：

1. 发起前：规则的简短说明与“开始严格扫描”。
2. 请求中：只显示“扫描正在运行，请保持此页面打开”，不显示伪造百分比。
3. 已完成或无候选：以四格紧凑 HUD 显示服务端返回的 `certificates_seen`、`roots_observed`、`strict_rejections`、`candidates_created`；并用文案明确区分有候选和无候选。
4. 失败：红色错误区，包含可复制的服务端错误摘要与重试按钮。

HUD 只呈现服务端字段，不从字段自行计算“成功率”“延迟”或“通过数量”。

## 6. 独立候选详情页

### 6.1 双栏布局

桌面使用左侧主阅读区、右侧粘性审核决策区：

- 左侧：返回收件箱、身份区、新网站与可访问性证据、产品判断、原始审计数据；
- 右侧：审核人、审核状态、批准/暂缓/拒绝/拉黑动作；
- 移动端：主阅读区单列，审核动作固定于底部。

### 6.2 证据区

证据按可读的“事实行”呈现：状态、标题、简短解释、可用时的时间、URL 与原文。原始审计继续默认折叠，等宽可复制。

### 6.3 决策区

- 当前审核人未设置时，操作后弹出 ID 输入对话框；设置后由本浏览器保存。
- 批准为主操作，但明确说明它只代表内部人工审核，不会自动公开发布。
- 拒绝和拉黑保留二次确认。
- 成功后回到收件箱；冲突后提示刷新；提交中禁用同一区域的重复操作。

## 7. 验收

1. 深色与浅色主题均可切换且刷新后保留，文本对比度足够阅读。
2. 首页在桌面和 390px 宽度下均能识别最高优先级候选及其真实状态。
3. 缺失严格快照的历史候选仍显示“未验证”。
4. 详情页有独立 URL、桌面粘性审核区与移动固定操作区，且不自动进入下一候选。
5. 扫描 HUD 的四个数字来自真实 POST 响应；失败、无候选和成功在视觉与文案上不同。
6. 既有 API 与审核流程测试继续通过；浏览器控制台无未处理错误。
